PERSISTENT MOBILE WORKSPACE

Manage multiple tmux projects from Android

Use TerminalHub as the mobile control surface for several projects running on your own SSH servers. Each project gets a saved Android tab; tmux keeps its remote shell and processes alive when the connection disappears.

No companion computer is required.

You configure, start, inspect, and switch projects from the phone. At least one reachable server is still required because that is where the remote shells and processes run.

What persists where

TerminalHub on Android

Stores server and project profiles, open tabs, tab order, the active tab, and reconnect state.

tmux on the server

Keeps the remote shell, command output, and long-running processes alive across SSH disconnects and app restarts.

A live SSH socket is useful but not the durable state. Optional background SSH can reduce reconnects while switching apps, but tmux remains the recovery mechanism.

1. Prepare each server

Install an SSH server, tmux, Git, and the tools used by your projects. This Debian/Ubuntu example creates a common parent directory:

sudo apt update
sudo apt install openssh-server tmux git
mkdir -p "$HOME/terminalhub"
tmux -V

For macOS, enable Remote Login and install tmux with brew install tmux. Prefer a private network or VPN such as Tailscale instead of exposing password-based SSH directly to the internet.

2. Add and verify the server in TerminalHub

  1. Create a server profile.

    Enter a display name, hostname or IP address, SSH port, username, and projects folder such as ~/terminalhub.

  2. Configure authentication.

    Generate an SSH key in TerminalHub, install its public key with a one-time password, or paste an existing private key. Never copy the private key to the server.

  3. Run Test SSH.

    On first contact, independently compare the displayed SHA-256 host-key fingerprint with the intended server before choosing Trust and reconnect.

3. Create one profile per project

Each TerminalHub project combines a server, remote folder, tmux session, startup script, optional Git repository, and terminal tab. Keep Use tmux enabled for persistent remote projects.

The default custom script changes to {{PROJECT_PATH}}. TerminalHub derives a shell-safe tmux name from the project name. A custom command starts only when a new tmux session is created, so reconnecting does not deliberately launch duplicates.

4. Build the tab workspace

  1. Open the first project. TerminalHub prepares its directory, creates the named tmux session, and adds a tab.
  2. Open additional projects on the same server or on other servers.
  3. Tap a tab to switch projects, reorder tabs to match your workflow, or swipe the special-key bar to move between connected tabs.
  4. Use the multiline input panel for longer commands, pasted instructions, or text prepared with Android voice input.
  5. Upload Android files into the active project, or open HTTP(S) links from terminal output in the phone's browser.

5. Disconnect and restore safely

Leaving the app or changing networks may disconnect SSH. The project tab should remain visible. Reconnect the individual tab or use Reconnect all; TerminalHub opens replacement connections in parallel and keeps the tab that was active when reconnect began.

# Server-side check if a tab does not restore as expected
tmux ls

# Attach manually for diagnosis
tmux attach -t project-session-name

If Android killed the app, reopening it reconstructs the saved tab workspace and reconnects to the server. Existing tmux sessions are reused, so their commands and processes remain available.

Troubleshooting

The tab reconnects but the process is gone

Confirm that the project uses tmux and that the process was started inside its tmux session. Check tmux ls on the server.

Several tabs ask about the same new host key

TerminalHub groups matching first-contact prompts for the same host and port. Verify the fingerprint once through an independent channel, then approve the grouped reconnect.

The server key changed unexpectedly

Stop. Do not replace trust automatically. Verify the server was legitimately rebuilt, then use Forget trusted key in the server editor and run Test SSH again.

Android reconnects too often while switching apps

Enable the optional user-controlled background SSH setting. It displays an ongoing notification and Stop action. Android can still terminate the process; tmux remains the fallback.

Security checklist

  • Use SSH keys and protect the server account.
  • Verify every first-contact host-key fingerprint independently.
  • Use a VPN or restricted firewall rules where practical.
  • Do not paste passwords, private keys, tokens, or unredacted logs into public issues or AI conversations.
  • Remember that server-side programs can read data available to that server account.
