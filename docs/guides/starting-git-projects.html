PHONE-FIRST PROJECT SETUP

Start remote Git projects from Android

Create a project profile on the phone, let your server clone the repository, and keep the resulting shell in a persistent TerminalHub tab. The server does the build and execution work; Android remains the control surface.

Before you start

  • TerminalHub installed on Android.
  • A Linux or macOS server reachable from the phone over SSH.
  • git and preferably tmux installed on that server.
  • The server account can authenticate to the Git host when the repository is private.
Two SSH relationships may be involved.

TerminalHub authenticates from Android to your server. The server separately authenticates to GitHub, GitLab, or another Git host. A successful TerminalHub connection does not automatically give the server access to a private repository.

1. Prepare Git access on the server

Log in to the server account and verify the tools:

git --version
tmux -V
mkdir -p "$HOME/terminalhub"

For a private GitHub repository, configure an SSH key or another credential on the server and test it there:

ssh -T git@github.com
git ls-remote git@github.com:OWNER/REPOSITORY.git HEAD

Follow your Git provider's current authentication guidance. Do not put a personal access token directly in a TerminalHub project URL or public configuration export.

2. Add the server to TerminalHub

  1. Create a server profile with host, port, username, authentication, and projects folder.
  2. Run Test SSH.
  3. On first contact, compare the displayed SHA-256 host-key fingerprint through an independent channel before trusting it.

3. Create the project profile

TerminalHub normalizes GitHub HTTPS repository URLs to SSH form when they are saved. That avoids embedding web credentials, but it also means the server must have working SSH access to GitHub.

4. Open the project from the phone

On first open, TerminalHub follows this sequence:

resolve the server's projects folder
└─ create the project folder, or shallow-clone the Git repository
   └─ create the named tmux session
      └─ attach the Android terminal
         └─ run the custom script
            └─ run the optional custom command

When you later reconnect to the same running tmux session, TerminalHub skips the script and custom command so it does not intentionally start a second development server or agent.

5. Work entirely from Android

  • Use the terminal tab for Git, builds, editors, logs, server tools, or optional AI terminal agents.
  • Use multiline input for longer commands or pasted instructions.
  • Upload one or more Android files into the active project or share a file to TerminalHub from another app.
  • Download a top-level project file through Android's destination picker and open the completed file with a compatible app.
  • Tap HTTP(S) links printed by a development server to open them in the phone's browser.
  • Create more project profiles and switch among them in the persistent tab bar.

Useful project patterns

Existing repository

Set a Git URL and let TerminalHub shallow-clone it on the first open.

New empty project

Leave Git URL empty. TerminalHub creates the project directory; initialize it with git init from the tab.

Long-running development server

Use tmux and set the custom command to the development server command.

Interactive coding agent

Install the agent on the server and use its CLI command as the optional custom command. The AI service is not bundled with TerminalHub.

Troubleshooting clone failures

Permission denied (publickey) from the Git host

The server, not Android, lacks Git-host authentication. Run ssh -T and git ls-remote as the same server user configured in TerminalHub.

The repository URL works on a laptop but not the server

Credentials and SSH agents are machine-specific. Configure access for the remote server account and confirm DNS/network access from that server.

The project directory exists but is not a Git checkout

TerminalHub only clones when the expected checkout is absent. Inspect the remote directory, move conflicting files safely, or clone manually. Avoid deleting data until it is backed up.

The startup command does not run after reconnecting

This is expected when reattaching an existing tmux session. TerminalHub avoids rerunning startup commands that could create duplicate processes.

Security boundaries

  • TerminalHub does not host the repository or server.
  • Git credentials remain the responsibility of the configured server account.
  • Configuration export excludes TerminalHub credentials, but review any exported file before sharing it.
  • Never include secrets in project names, Git URLs, custom scripts, screenshots, issues, or support logs.
